# KIIP 문제 출제·검수 기준 및 체크리스트

## 문서 목적

이 문서는 CoreRing의 KIIP 단계형 연습 문제를 추가하거나 수정할 때 사용하는 출제·검수 기준이다. 목표는 단순히 문법적으로 맞는 문제를 만드는 것이 아니라, **실제 생활에서 자연스럽고, 정답이 하나로 명확하며, 학습자가 왜 맞고 틀렸는지 이해할 수 있는 문제**를 제공하는 것이다.

CoreRing의 KIIP 연습은 공식 KIIP 과정이나 시험을 대체하지 않는다. 공식 교재를 그대로 복제하지 않고, CoreRing에서 발생하는 실생활 번역·대화 문맥과 자체 제작 학습 문항을 연결하는 보강 레이어로 운영한다.

---

## 1. 출제 원칙

### 1.1 생활 문맥 우선

문제는 실제로 한국 생활에서 만날 수 있는 장면에서 출발한다. 인사, 병원, 은행, 교통, 식당, 쇼핑, 직장, 학교, 행정기관, 이웃과의 대화처럼 학습자가 바로 사용할 수 있는 상황을 우선한다.

문장만 보면 맞지만 실제 대화에서는 거의 쓰지 않는 표현, 지나치게 교과서적인 표현, 상황과 관계에 맞지 않는 높임말은 사용하지 않는다.

### 1.2 한 문제에는 한 가지 학습 목표

한 문제에서 어휘, 조사, 높임말, 시제, 문화적 예절을 동시에 묻지 않는다. 학습자가 틀렸을 때 무엇을 몰랐는지 설명할 수 있어야 한다.

문항마다 다음 중 하나를 주 학습 목표로 지정한다.

| 학습 목표 | 예시 |
|---|---|
| 어휘 의미 | `정류장`의 의미 고르기 |
| 기본 문법 | `-에`, `-에서` 구별하기 |
| 기능 표현 | 부탁, 사과, 감사, 거절하기 |
| 상황 응답 | 병원·식당·은행에서 자연스러운 응답 고르기 |
| 숫자·시간 | 가격, 날짜, 시각 표현하기 |
| 높임말·말투 | 처음 만난 사람에게 적절한 표현 고르기 |

### 1.3 정답은 하나만 가능해야 함

문법적으로 가능한 답이 두 개 이상이거나, 상황에 따라 두 답 모두 자연스러운 경우에는 출제하지 않는다. 정답을 하나로 만들기 위해 억지로 어색한 문장을 추가하지 말고, 문맥을 보강하거나 문제를 다시 쓴다.

### 1.4 답을 몰라도 찍을 수 있는 문제를 피함

정답만 길거나, 유일하게 존댓말인 선택지, 유일하게 문법적으로 완성된 선택지처럼 형식만 보고 답을 찾을 수 있으면 수정한다. 선택지는 길이·품사·말투를 가능한 한 맞춘다.

### 1.5 해설은 정답의 반복이 아니어야 함

해설에는 최소한 다음 두 가지를 포함한다.

1. 왜 이 답이 상황에 맞는지
2. 학습자가 다음에 어디에서 사용할 수 있는지

예: “`삼천 원`은 가격을 말할 때 사용하는 표현이에요. 물건의 가격을 물을 때는 `얼마예요?`라고 하고, 대답할 때는 숫자와 `원`을 함께 말해요.”

## 2. 한국어 자연스러움 검수

다음 질문에 모두 “예”라고 답할 수 있어야 한다.

- [ ] 한국어 원어민이 실제 상황에서 이 문장을 들었을 때 어색하지 않은가?
- [ ] 문장 안의 조사, 어미, 높임말, 시제가 서로 맞는가?
- [ ] 주어가 생략되어도 상황을 이해할 수 있는가?
- [ ] `은/는`, `이/가`, `을/를`, `에/에서`가 문맥에 맞는가?
- [ ] 수사와 단위 명사가 올바르게 결합하는가?
- [ ] 한자어 수사와 고유어 수사를 구분해야 하는 상황에서 올바른 체계를 사용했는가?
- [ ] 가격, 날짜, 시간, 나이, 개수 표현이 실제 관용 방식과 맞는가?
- [ ] `안`과 `못`, `있어요`와 `계세요`, `줘요`와 `주세요`를 상황에 맞게 구분했는가?
- [ ] 반말·해요체·하십시오체가 대화 참여자 관계에 맞는가?
- [ ] 직역투 또는 번역투 표현이 남아 있지 않은가?
- [ ] 문장부호와 띄어쓰기가 학습용 표기로 적절한가?
- [ ] 한 문장 안에 불필요하게 어려운 어휘가 섞여 있지 않은가?

### 숫자·단위 집중 검수

숫자 문제는 별도의 검수를 한다. 특히 다음을 확인한다.

| 상황 | 기본 원칙 | 예시 |
|---|---|---|
| 가격·금액 | 한자어 수사 | 삼천 원, 만 원 |
| 시각 | 시는 고유어, 분은 한자어 | 세 시 십 분 |
| 날짜 | 월·일은 한자어 수사 | 십월 십삼일 |
| 개수 | 대상에 따라 고유어 수사 | 사과 세 개 |
| 사람 수 | 명/분과 문맥에 맞는 수사 | 세 명, 세 분 |
| 나이 | 살은 고유어, 세는 한자어도 가능 | 스무 살, 이십 세 |

> “세 원”처럼 형식상 조합은 가능해 보여도, 가격 문맥에서 실제로 자연스러운 표현인지 다시 확인한다. 가격 문제라면 “삼천 원”처럼 현실적인 금액을 사용하고, 개수 문제라면 “사과 세 개”처럼 단위와 문맥을 일치시킨다.

## 3. 문맥·상황 검수

문제의 대화만 읽고도 누가 누구에게, 어떤 장소에서, 왜 말하는지 이해할 수 있어야 한다.

- [ ] 장소가 필요한 문제라면 장소가 드러나는가?
- [ ] 화자 간 관계가 필요한 문제라면 관계나 말투가 드러나는가?
- [ ] 질문과 대답의 정보 유형이 맞는가? (`어디`에는 장소, `언제`에는 시간 등)
- [ ] 대답이 질문에 직접 답하고 있는가?
- [ ] 앞 문장과 뒤 문장이 논리적으로 연결되는가?
- [ ] 한국 생활에서 실제로 필요한 장면인가?
- [ ] 문화적으로 오해를 만들 수 있는 상황은 아닌가?
- [ ] 특정 지역·세대·직업에만 통하는 표현이면 범위를 표시했는가?
- [ ] 대화 참여자의 감정과 말투가 상황에 맞는가?
- [ ] 문맥 없이도 답이 너무 쉽게 보이거나, 반대로 문맥이 부족해 여러 답이 가능한가?

### 상황별 추가 확인

| 상황 | 반드시 확인할 것 |
|---|---|
| 식당 | 주문·계산·식사 전후 표현이 섞이지 않았는가 |
| 병원 | 증상과 요청 표현이 구분되는가 |
| 은행 | 존댓말과 숫자·금액이 자연스러운가 |
| 직장 | 상하 관계에 맞는 말투인가 |
| 학교 | 선생님·친구·행정실 대상 말투가 다른가 |
| 행정기관 | 지나치게 반말인 표현이 없는가 |
| 교통 | 장소·방향·시간 질문이 구분되는가 |
| 쇼핑 | 가격·수량·색상·사이즈 질문이 구분되는가 |

## 4. 선택지와 오답 검수

### 4.1 정답 검수

- [ ] 정답이 질문과 문맥에 정확히 맞는가?
- [ ] 정답 문장을 완성했을 때 조사·어미가 자연스러운가?
- [ ] 정답만 문법적으로 완전한 형태가 아닌가?
- [ ] 정답을 다른 선택지로 바꿔도 문맥이 성립하지 않는가?

### 4.2 오답 검수

좋은 오답은 단순히 무작위 단어가 아니라, 학습자가 실제로 혼동할 수 있는 답이다. 다만 오답도 문법적으로는 문장 구조에 맞아야 한다.

- [ ] 오답은 학습 목표와 관련된 혼동 포인트인가?
- [ ] 오답을 넣었을 때 문장 형태가 깨지지 않는가?
- [ ] 모든 선택지의 품사와 말투가 가능한 한 비슷한가?
- [ ] 정답만 유난히 길거나 짧지 않은가?
- [ ] 오답이 너무 엉뚱해서 생각 없이 제거할 수 있지 않은가?
- [ ] 오답이 다른 상황에서는 정답이 될 수 있다면, 현재 문맥에서 왜 안 되는지 설명 가능한가?

### 4.3 선택지 형태 규칙

- 뜻 고르기 문제는 같은 언어의 표현끼리 비교한다.
- 빈칸 문제는 문장에 넣었을 때 같은 품사·단위가 되도록 만든다.
- 상황 응답 문제는 모두 실제 대화에서 가능한 문장으로 만든다.
- `모두 맞음`, `위의 것 없음` 같은 선택지는 초기 단계에서 사용하지 않는다.
- 선택지 순서는 고정하지 않고 seed 데이터에서 섞을 수 있도록 한다.

## 5. 베트남어·다국어 품질 검수

현재 CoreRing의 KIIP MVP는 한국어·베트남어 학습 흐름을 기준으로 한다. 베트남어 문항을 추가할 때는 직역보다 실제 사용 표현을 우선한다.

- [ ] 베트남어 뜻이 한국어 원문의 핵심 의미를 정확히 전달하는가?
- [ ] 호칭·존칭·상황에 맞는 베트남어 말투인가?
- [ ] 북부·남부 차이가 있는 표현이면 지역 차이를 표시했는가?
- [ ] 한국어의 높임말을 베트남어에서 과도하게 일대일 대응시키지 않았는가?
- [ ] 베트남어 선택지의 성조와 철자가 정확한가?
- [ ] 한국어와 베트남어를 섞어 쓰는 선택지가 의도된 것인가?
- [ ] 번역문이 사전식 의미가 아니라 해당 문맥의 의미인가?
- [ ] 베트남어 원어민 또는 검수 가능한 번역 담당자가 확인했는가?

다국어 확장 시에는 문항 원본과 번역을 분리하고, 번역이 없는 언어는 자동으로 공개하지 않는다. 번역 품질이 낮은 상태에서 언어 수만 늘리지 않는다.

## 6. 학습 난이도와 단계 적합성

KIIP 1단계 문제는 학습자가 문장을 처음부터 모두 해석해야 하는 고난도 문제가 아니라, 생활 장면에서 자주 쓰는 기초 표현을 익히는 수준이어야 한다.

- [ ] 1단계 학습자가 알고 있어야 할 기본 어휘·표현인가?
- [ ] 문제를 풀기 위해 불필요한 고급 어휘를 알아야 하지 않는가?
- [ ] 한 문제의 핵심 난점이 하나인가?
- [ ] 정답을 맞힌 뒤 바로 사용할 수 있는 표현인가?
- [ ] 해설이 다음 사용 장면을 보여주는가?
- [ ] 오답이 학습자를 좌절시키기보다 혼동 포인트를 알려주는가?
- [ ] 같은 표현을 반복하되 문맥은 조금씩 바꾸고 있는가?
- [ ] 한 세션 안에서 뜻·문맥·응답 문제의 비율이 한 유형에 치우치지 않는가?

### 권장 세션 구성

5문제 세션은 다음처럼 구성하는 것을 권장한다.

| 순서 | 유형 | 목적 |
|---|---|---|
| 1 | 뜻 고르기 | 핵심 어휘 확인 |
| 2 | 문맥 빈칸 | 문장 안에서 사용 |
| 3 | 상황 응답 | 실제 대화 선택 |
| 4 | 문맥 빈칸 | 다른 상황에서 재사용 |
| 5 | 상황 응답 | 최종 회상과 적용 |

## 7. 해설·핵심 표현 검수

- [ ] 해설이 정답을 그대로 반복하지 않는가?
- [ ] 정답이 사용되는 이유를 설명하는가?
- [ ] 학습자가 실제로 다시 사용할 수 있는 예문이 있는가?
- [ ] 오답이 왜 현재 상황에 맞지 않는지 필요한 경우 설명하는가?
- [ ] 핵심 표현이 문제의 정답 또는 학습 목표와 일치하는가?
- [ ] 핵심 표현의 반대 언어 뜻이 정확한가?
- [ ] 해설의 난이도가 문제보다 지나치게 높지 않은가?
- [ ] 설명에 예외를 너무 많이 넣어 기초 학습을 방해하지 않는가?

## 8. 기술·데이터 검수

문항의 언어 품질이 좋아도 데이터가 잘못되면 운영에서 잘못된 답을 제공할 수 있다.

- [ ] `id`가 고유한가?
- [ ] `stage`와 문제 난이도가 일치하는가?
- [ ] `type`이 `meaning`, `context`, `response` 중 하나인가?
- [ ] `choices`가 4개인가?
- [ ] `answerIndex`가 0부터 시작하고 선택지 범위 안에 있는가?
- [ ] API의 `get-session` 응답에 정답 인덱스가 노출되지 않는가?
- [ ] `submit-answer`가 서버의 정답을 기준으로 판정하는가?
- [ ] 존재하지 않는 문제 ID나 잘못된 선택지 인덱스를 거부하는가?
- [ ] `x-device-id` principal 검증을 통과해야 문제를 요청할 수 있는가?
- [ ] 문제·선택지·해설에 빈 문자열이나 불필요한 HTML이 없는가?
- [ ] 한글 줄바꿈이 실제 화면에서 읽기 좋게 표시되는가?
- [ ] 선택지를 섞어도 `answerIndex`가 올바르게 유지되는가?

## 9. 배포 전 최종 체크리스트

각 문항을 공개하기 전에 출제자와 별도 검수자가 각각 확인한다.

### 문항 단위

- [ ] 출제자가 문제의 정답과 학습 목표를 설명할 수 있다.
- [ ] 별도 검수자가 문맥만 보고 정답을 하나로 선택한다.
- [ ] 한국어 원어민 검수가 완료되었다.
- [ ] 베트남어 번역 검수가 완료되었다.
- [ ] 실제 생활에서 사용할 장면이라는 판단이 있다.
- [ ] 해설이 정답과 핵심 표현을 정확히 설명한다.
- [ ] 오답이 문법적으로 깨지지 않고 학습적으로 의미가 있다.
- [ ] 단계 난이도가 적절하다.

### 묶음 단위

- [ ] 세션 안에 같은 정답 패턴이 반복되지 않는다.
- [ ] 문제 유형이 한 가지에 치우치지 않는다.
- [ ] 같은 단어가 문맥만 바뀌어도 자연스럽게 재사용된다.
- [ ] 민감한 문화·지역·관계 표현이 별도 검토되었다.
- [ ] 번역 언어별로 공개 가능한 문항 수가 충분하다.

### 코드·배포 단위

- [ ] `npm run build`가 통과한다.
- [ ] 새 API route가 build 결과에 포함된다.
- [ ] KIIP API ESLint가 통과한다.
- [ ] 세션 응답에 정답이 노출되지 않는다.
- [ ] 대표 문제 하나를 실제 POST 요청으로 생성한다.

## 10. 문제 승인 등급

| 등급 | 의미 | 처리 |
|---|---|---|
| A | 자연스럽고 정답이 명확하며 바로 공개 가능 | 승인 |
| B | 의미는 맞지만 표현·해설을 조금 개선할 수 있음 | 수정 후 승인 |
| C | 정답이 애매하거나 문맥이 부족함 | 재출제 |
| D | 문법·번역·문화적으로 잘못됨 | 폐기 후 재작성 |

다음 항목이 하나라도 있으면 A 등급을 주지 않는다.

- 정답이 두 개 이상 가능한 경우
- 원어민이 실제로 잘 쓰지 않는 표현인 경우
- 가격·시간·날짜·개수의 수사 체계가 잘못된 경우
- 번역이 핵심 의미를 바꾸는 경우
- 해설이 정답과 모순되는 경우
- 단계 수준을 크게 벗어나는 경우
